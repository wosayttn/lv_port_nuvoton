## 一、產品目標
本產品為電鍋／電子鍋的人機介面展示系統，透過 TFT LCD 與 4 顆實體按鍵，提供使用者完成模式選擇、烹煮啟動、烹煮中監看與完成提示等操作流程。

產品設計目標如下：
- 提供簡單、直觀的烹煮操作流程。
- 以有限按鍵完成全部 UI 導覽與控制。
- 將 UI 畫面與韌體狀態機直接對應，方便嵌入式實作。
- 可在 RTOS 或 bare-metal 架構中運作，不依賴大型框架。

## 二、系統範圍
本需求文件涵蓋以下範圍：
- TFT LCD 畫面功能與畫面流。
- 4 顆實體按鍵的功能定義。
- 烹煮相關顯示與控制邏輯。
- 狀態機式 UI 架構。
- 與硬體輸入輸出相關的基本互動需求。

不涵蓋內容：
- 加熱演算法細節。
- 感測器校正方式。
- 通訊協定、雲端功能或資料同步。
- 完整外觀設計與美術規範。

## 三、硬體相關需求

### 3.1 顯示介面
- 系統需具備 TFT LCD 顯示器，作為主要 UI 輸出介面。
- TFT LCD 應負責顯示主畫面、模式選單、烹煮資訊、完成通知與保溫狀態。

### 3.2 實體按鍵
- 系統需具備 4 顆實體按鍵：`MENU`、`UP`、`DOWN`、`START`。
- 每顆按鍵需對應單一韌體處理入口。
- 按鍵輸入需支援：
	- 去抖動（debounce）
	- 長按判定（long-press）

### 3.3 蜂鳴器
- 系統需具備蜂鳴器，用於提示音回饋。
- 蜂鳴器至少需在烹煮完成時發出提示。
- 可用於按鍵操作或狀態切換的聲音回饋。

### 3.4 溫度感測
- 系統需具備溫度感測器。
- 溫度資料需用於加熱控制，形成閉迴路控制基礎。

### 3.5 加熱控制
- 系統需具備加熱器控制能力。
- 韌體需可依據烹煮流程與溫度狀態驅動加熱功率級。

### 3.6 計時功能
- 系統需具備計時功能。
- 計時功能應支援 RTC-based scheduling。
- 主畫面需顯示目前時間。

## 四、使用者操作需求

### 4.1 按鍵功能定義

| 按鍵 | 主要功能 | 次要／情境功能 |
| --- | --- | --- |
| MENU | 從主畫面進入選單 | 返回上一層或離開當前畫面 |
| UP | 游標上移 | 增加數值（時間、溫度等） |
| DOWN | 游標下移 | 減少數值（時間、溫度等） |
| START | 確認選擇／開始烹煮 | 暫停／停止烹煮流程 |

### 4.2 操作原則
- 使用者應可僅透過 4 顆按鍵完成全部操作。
- 操作流程應儘量減少從開機到開始烹煮的步驟數。
- 不同畫面中，按鍵的情境功能需保持一致且可預期。

## 五、UI 與狀態機需求

### 5.1 狀態機架構
- UI 應採用簡單狀態機架構。
- 每個畫面皆應對應一個明確的系統狀態。
- 每個狀態需具備明確的進入（entry）與離開（exit）行為。
- 狀態列舉（state enums）應可直接對應到畫面處理函式或狀態處理函式。

### 5.2 架構要求
- 架構應利於韌體實作與狀態切換。
- 架構應可同時適用於：
	- RTOS 環境
	- bare-metal 環境
- 架構不應依賴大型或複雜 UI framework。

### 5.3 畫面一致性
- 各畫面版面配置應保持一致。
- 建議固定版面區域如下：
	- 上方：狀態列
	- 中央：主要內容區
	- 下方：按鍵提示或 soft-key hints

## 六、主要畫面需求

### 6.1 Home／Ready 狀態畫面
- 系統在待機時需顯示 Home 畫面。
- 畫面需包含：
	- 目前時間
	- Ready／待機指示
	- 提示使用者按 `MENU` 進入選單

### 6.2 Menu／Mode Selection 畫面
- 使用者按下 `MENU` 後，系統需進入模式選單畫面。
- 選單需支援捲動式列表操作。
- 至少需包含以下模式：
	- White Rice
	- Quick Cook
	- Porridge
	- Steam
	- Keep Warm
- 使用者應可透過 `UP` / `DOWN` 切換項目，並透過 `START` 確認選擇。

### 6.3 Cooking 畫面
- 進入烹煮後，系統需顯示烹煮中畫面。
- 畫面至少需顯示：
	- 剩餘時間倒數
	- 溫度資訊或溫度曲線
- `START` 按鍵在此畫面需支援暫停／恢復功能。
- 系統應可在烹煮中顯示目前流程狀態。

### 6.4 Finish／Keep Warm 畫面
- 烹煮完成後，系統需觸發蜂鳴器提示。
- 系統需自動切換至 Keep Warm 狀態。
- 保溫狀態需維持保溫溫度並提供對應畫面顯示。

## 七、流程需求

### 7.1 基本流程
1. 開機後進入 Home／Ready 畫面。
2. 使用者按下 `MENU` 進入模式選單。
3. 使用者使用 `UP` / `DOWN` 選擇模式。
4. 使用者按下 `START` 確認並開始烹煮。
5. 系統進入 Cooking 畫面並顯示倒數與溫度資訊。
6. 烹煮完成後蜂鳴器提示。
7. 系統自動切換至 Keep Warm 狀態。

### 7.2 畫面切換原則
- `MENU` 應提供返回或退出當前畫面的能力。
- 狀態切換時需確保畫面與實際控制狀態一致。
- 在任何可調整數值的畫面中，`UP` / `DOWN` 需負責數值增減。

## 八、非功能需求
- 韌體架構需易於維護與擴充新模式。
- 畫面流程需簡潔，適合嵌入式裝置操作習慣。
- 響應應具有即時性，按鍵操作後應有明確 UI 或聲音回饋。
- 需支援低資源嵌入式環境，不依賴高成本執行平台。

## 九、待確認項目
以下內容未在簡報中明確定義，後續應補齊：
- 各烹煮模式的實際控制參數（時間、目標溫度、加熱曲線）。
- 暫停與停止是否為不同狀態，以及 `START` 長按／短按的精確行為。
- Keep Warm 模式的目標溫度與退出條件。
- 畫面尺寸、解析度、配色與字體規範。
- 錯誤處理機制，例如感測器異常、過熱、空鍋、按鍵異常。
- 排程功能的使用情境與設定方式。
